DumpAnalyzer — ways analysis gets triggered (current build)

Verified against src/scheduler.rs, src/sync.rs, src/agent.rs on 2026-10-14 (phase 2).

Four automatic paths plus token-guarded manual triggers (added 2026-10-14).

  • Manual (2026-10-14): POST /-/analyze (one dump → report) and POST /-/rescan (full sweep), both bearer-guarded; plus a 60 s idle replay sweep for pending local verdicts.
  • Boot scan is the catch-up: the full catalog is paged at every start.
  • Event feed is the steady state: new intake becomes a job within one poll interval.
  • Crash recovery re-runs interrupted jobs and settles write-back — per the TLA+ spec (CrashReset / reconcile), MBT-replayed against the real store.
  • Retry is bounded: attempt budget per job (default 2), then terminal failed; verdict-failed is a report, infra failure is not.

Remaining candidate: a scan-once CLI subcommand for a stopped daemon (the instance lock forbids it while running).
